Target: Windows 11 22H2, build 22621.6060, ntfs.sys 10.0.22621 (DateStamp 5c707063)
Captured over KDNET.

    Arg2 = 0x0000000000000000   0 = the operation was a READ

Driver at fault: Ntfs.sys - Address FFFFF80317097E49 base at FFFFF80317060000

Interpretation
--------------
The faulting instruction is the memmove/memcpy inside NtfsQueryEaSimpleScan that
copies an EA entry. Its length is 9 + EaNameLength + EaValueLength taken from the
on-disk EA entry with no bound against the EA stream size. When that length runs
the copy off the end of the mapped EA region, the kernel reads an unmapped page
-> unhandled kernel page fault -> bugcheck 0x50. Read access (Arg2=0) on a kernel
address (Arg1) originating in Ntfs's copy routine.

How this run forced it
----------------------
The natural on-disk over-read is bounded to ~64 KB (EaValueLength is a USHORT and
NTFS caps total EA size at 64 KB), which frequently stays inside mapped memory and
merely leaks (see out_selfcontained_read.txt / bytesReturned=1041 and the 0x10010
64 KB leak). To demonstrate the crash *consequence* deterministically, the copy
length was extended under the kernel debugger (r8=0x40000000) at the exact memmove,
so the read crosses an unmapped boundary every time. In the wild the same bugcheck
occurs whenever pool/cache layout places an unmapped page within the ~64 KB
over-read window.
